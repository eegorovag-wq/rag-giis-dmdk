# RAG-помощник по ГИИС ДМДК на n8n

Помощник отвечает на вопросы о работе в ГИИС ДМДК. Отвечает только по официальному руководству пользователя (версия 5.1.4, АО «Гознак», 245 страниц) и называет страницу, на которую опирается. Если в руководстве ответа нет, говорит «В руководстве этого не нашла» и не придумывает.

Всё работает на одном компьютере. Документы никуда не отправляются, ключи внешних API не нужны.

## Зачем

ГИИС ДМДК — обязательная система для всех, кто продаёт ювелирные изделия. Руководство по ней большое, и найти ответ на простой вопрос («за сколько дней передать продажу?», «как дать доступ техподдержке?») долго. Я веду в этой системе свой ИП (ювелирные изделия 925 пробы), поэтому вопросы для проверки взяты из реальной работы.

## Как устроено

```
Загрузка (один раз):
  руководство PDF ─► prepare_docs.py ─► фрагменты с пометкой [стр. N, раздел] ─► n8n:
  прочитать файл ─► нарезать ─► эмбеддинги bge-m3 (Ollama) ─► векторное хранилище

Вопрос:
  чат n8n или POST /webhook/giis-ask {"question": "..."}
  ─► эмбеддинг вопроса ─► 4 ближайших фрагмента ─► qwen2.5:7b (Ollama) отвечает только по ним
  ─► {"output": "... Источник: стр. N"}
```

| Часть | Что использовано |
|---|---|
| Оркестрация | n8n 2.46 в Docker (`docker-compose.yml`) |
| Эмбеддинги | `bge-m3` через Ollama: многоязычная модель, хорошо работает с русским |
| Ответы | `qwen2.5:7b` через Ollama, temperature 0.1 |
| Хранилище | Simple Vector Store n8n (в памяти) |
| Подготовка текста | `prepare_docs.py` (Python, pypdf) |
| Проверка качества | `eval/` — 15 вопросов с ответами из руководства и скрипты прогона |

Сценарий n8n лежит в `workflow-rag-giis-dmdk.json`.

## Проверка качества

15 вопросов (`eval/questions.json`):
- **12** — ответ есть в руководстве, для каждого записаны правильный факт и страница;
- **3** — ответа в руководстве нет (коды Честного знака, ставка НДС, стоимость подключения). Модель должна отказаться отвечать.

Каждый ответ я оценивала вручную. Скрипт ищет ключевые слова, но это только подсказка для оценки.

| | Первая версия | После исправлений |
|---|---|---|
| Верные ответы (из 12) | 7 (+1 неполный) | **11** |
| Выдуманные ответы | **2** | **0** |
| «Не нашла», хотя ответ есть | 2 | 1 |
| Честный отказ, когда ответа нет (из 3) | 3 | 3 |
| Время ответа на CPU | 40–105 с | 35–150 с |

### Что было не так и как нашла

1. **Поиск цеплялся за оглавление и журнал изменений.** На вопрос о сроке постановки на спецучёт база выдавала оглавление: там упоминается «специальный учёт», но ответа нет. Решение — `prepare_docs.py`:
   - выбрасывает титул, оглавление и журнал изменений;
   - убирает служебную рамку листа («Изм. Лист № докум. Подп. Дата»);
   - в начало каждого фрагмента пишет страницу и раздел. Модель видит их и может сослаться.
2. **В базе оставался только конец руководства.** Это главная находка. Я написала отдельную проверку поиска без модели (`eval/check_retrieval.py`). Она показала, что нужная страница стоит на 1-м месте во всех 12 вопросах. А n8n при этом приносил только страницы 149–228. Причина в настройке хранилища «Clear Store»: она очищает хранилище перед каждой пачкой эмбеддингов, а не один раз. В итоге в базе оставалась только последняя пачка. Поэтому вопросы про страницы 153–228 проходили, а про 17, 57 и 76 — нет, и на двух из них модель выдумала ответ.
   - Исправление: очистку отключила. Базу теперь обнуляет перезапуск n8n перед загрузкой (`eval/reload_and_eval.ps1`).
3. **Длинные инструкции обрезались.** Ответ на вопрос про групповую подпись оборвался на 10-м шаге: не хватило лимита длины ответа. Лимит подняла с 400 до 700 токенов.

Оставшаяся ошибка — вопрос 5 («сколько дней можно менять данные при курьерской доставке», ответ: 45 дней). Модель ответила «не нашла». Это ошибка в безопасную сторону: модель не выдумала ответ, а отказалась.

## Ограничения

- Хранилище в памяти: после перезапуска n8n руководство нужно загрузить заново (около 5,5 минут). Для постоянной работы стоит перейти на PGVector или Qdrant.
- На процессоре без видеокарты ответ идёт около минуты.
- 15 вопросов — небольшая проверка. Цифры показывают направление, а не точность в процентах.
- Руководство и текст из него в репозиторий не входят: это документ АО «Гознак». Его нужно скачать самостоятельно и положить в `docs/`.

## Запуск

```bash
ollama pull bge-m3
ollama pull qwen2.5:7b
docker compose up -d
python prepare_docs.py docs/<руководство>.pdf docs/giis-dmdk-chunks.txt
```

Дальше:
1. В n8n (http://localhost:5678) импортировать `workflow-rag-giis-dmdk.json`.
2. Создать учётные данные Ollama с адресом `http://host.docker.internal:11434`.
3. Опубликовать сценарий и запустить загрузку: `POST /webhook/giis-ingest`.
4. Задать вопрос в чате n8n или через `POST /webhook/giis-ask`.

Проверка: `powershell -File eval/reload_and_eval.ps1`.
